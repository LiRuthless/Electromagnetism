# Phase 6: 界面图表与面板体系 — 实现计划

> 本规约为已实现功能的回溯文档化（棕地逆向，2026-09-30 依据归档设计文档补齐）。

## 目标

为电磁场建模仿真工具提供完整的桌面界面骨架与图表交互体系：

1. 三栏布局：左侧赛道编辑与物理参数面板（默认 330px）｜中央磁场俯视图大画布｜右侧电感面板（默认 350px），左右面板均可拖拽调宽、可收起为 32px 窄条，内容按可折叠分区卡片组织；
2. 中央画布承载磁场热力图/等值线/赛道线/车体电感叠加/循迹轨迹叠加/转角刻度叠加，支持缩放平移与悬停探针；
3. 全部折线图统一缩放（框选/滚轮/平移/复位），除读数剖面图外均可"拖出"为画布上的浮动窗口，点击数据点联动车体位姿；
4. 顶栏提供标题、赛道总长、场计算进度、导出菜单与"恢复默认"入口。

## 背景与依据

- 使命关联（`specs/mission.md`）：本功能是"可视、可算、可验证"中**可视**的主体——磁场分布、电感读数、循迹结果均经本界面体系呈现，是调参与方案验证的人机入口。
- 技术约束（`specs/techstack.md`）：React 19 + TypeScript 严格模式 + Tailwind；折线图纯 SVG 自绘（recharts 仅用于实测对比预览图）；面板调宽用 react-resizable-panels 4.2.2；三枚 localStorage key 分工（app-state v6 / panel-layout / track-library）；appState schema 纪律与"回退不崩溃"为硬性约束。
- 前置条件：Phase 1 赛道几何（画布叠加与转角刻度依赖 `mathmodel/track.ts`）、Phase 2 磁场网格（热力图数据源）、Phase 3 电感读数与全程扫描（折线图数据源）、Phase 5 循迹闭环（轨迹叠加、Err(t)/轮速(t) 曲线与循迹轨迹电感图数据源）。
- 源依据：归档《程序设计说明.md》§1（界面布局段）、§3.1（面板收起/分区卡片化）、§3.2（画布）、§3.3（面板组织与全程扫描区）、§3.4–§3.8（缩放/浮动化/点击联动/顶栏/UI 组件化改造）。

## 实现顺序与依赖

1. Group 1 是全部后续工作的前提：三栏布局骨架确定左/右面板与中央画布三大挂载区，画布与图表先以内联形态就位；
2. Group 2 的 `useChartZoom` 封装是 Group 3"浮动窗内缩放保持可用"的前提；左侧栏收起独立可交付；
3. Group 3 依赖：浮动化依赖 Group 1 的中央画布区（portal 宿主）与 Group 2 的缩放封装；双图之②依赖 Phase 5 的 TrackingSensorChart 数据源；点击联动依赖位姿来源切换（Phase 5 交互，`specs/features/05-tracking-control/`）；
4. Group 4 依赖 Group 1–3 全部界面元素就位（改造对象是既有面板与图表）；panel-layout 持久化与 appState 解耦（`specs/features/07-persistence-export/`）。

## 风险与取舍

- **读数剖面图（SensorChart）不浮动化、不参与点击联动**（明确取舍）：其 x 轴为电感横向位置，无对应赛道位置语义；固定留在右栏。
- **panel-layout 与 appState 解耦、无版本号**（取舍）：宽度布局损坏/缺失只回退默认面板宽度，不丢工作状态，也不触发 `APP_STATE_VERSION` 升级。
- **分区卡片折叠、右栏收起、转角刻度开关均不持久化**（取舍）：视觉态视为会话内噪音，不进 schema；左侧栏收起因 2026-08-02 已入 v5 而保持持久化。
- **浮动窗为画布内 portal 层而非独立 OS 窗口**：状态表集中于 Home、经 `FloatingLayerContext` 下发，浮动状态可随 appState 持久化；代价是浮动范围限于中央画布（不越出主窗口）。
- **Select 溢出按根因修复而非逐处加宽**：触发框选中值槽位 `min-w-0 + flex-1 + truncate` 一次修复，各处仅再收敛过窄宽度与过长文案（完整说明入悬停 title）。
- **screenshot.cjs 以固定延时（6 s）等待场计算完成**（已知限制）：慢机器上可能需复跑截图；截图为目检辅助，不构成自动断言。
- 源文档未记载其他被排除方案。
